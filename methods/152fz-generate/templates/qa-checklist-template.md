# QA-чек-лист для {{SITE_DOMAIN}}

## Документы

- [ ] /policy/ открывается публично, без авторизации, по HTTPS;
- [ ] /personal-data-consent/ открывается публично, по HTTPS;
- [ ] в тексте политики все плейсхолдеры заменены на реальные данные;
- [ ] в тексте согласия все плейсхолдеры заменены на реальные данные;
- [ ] дата редакции проставлена в обоих документах;
- [ ] политика содержит раздел про cookie;
- [ ] политика и согласие не противоречат друг другу (одинаковые реквизиты, одинаковый список обработчиков);
{{#if OLD_POLICY_URL_DIFFERS}}- [ ] {{OLD_POLICY_URL}} отдаёт HTTP 301 на /policy/;{{/if}}

## Footer и страницы

- [ ] в footer есть ссылка «Политика обработки персональных данных» → /policy/;
- [ ] в footer есть ссылка «Согласие на обработку персональных данных» → /personal-data-consent/;
- [ ] в footer есть юр.блок с наименованием оператора, ИНН, ОГРН, адресом;
- [ ] обе ссылки работают на главной;
- [ ] обе ссылки работают на внутренних страницах ({{#if HAS_CART}}корзина, {{/if}}{{#if HAS_REGISTRATION}}личный кабинет, {{/if}}каталог);
- [ ] обе ссылки видны на mobile;

## Формы

Для каждой формы из form-checkboxes.md:

- [ ] чекбокс согласия виден рядом с формой;
- [ ] чекбокс не отмечен по умолчанию;
- [ ] чекбокс обязателен на клиенте;
- [ ] чекбокс обязателен на сервере (убрать required в DevTools — заявка не должна сохраниться);
- [ ] заявка успешно отправляется при отмеченном чекбоксе;
- [ ] обе ссылки в чекбоксе открывают правильные публичные URL в новой вкладке;
- [ ] на mobile текст чекбокса не обрезан.

(СГЕНЕРИРОВАТЬ: дополнительно для каждой формы из findings — отдельный мини-блок с именем формы и специфичными проверками. Например для регистрации Bitrix: «без галочки USER_PERSONAL_INFO регистрация не проходит». Для подписки: «снят checked с рубрики».)

## Cookie

- [ ] баннер появляется в чистой/incognito-сессии при первом посещении;
- [ ] ссылка из баннера открывает /policy/;
- [ ] после «Принять» баннер скрывается;
- [ ] cookie `cookieConsent=Y` сохраняется на 1 год;
- [ ] при повторном открытии баннер не появляется;
- [ ] на mobile не перекрывает важные элементы;

## Технические проверки

- [ ] все страницы используют HTTPS;
- [ ] нет mixed content (DevTools → Console);
- [ ] нет битых ссылок в legal-областях;
- [ ] страницы /policy/ и /personal-data-consent/ доступны для индексации;
- [ ] в политике и согласии не осталось `http://` (только `https://`).

## Завершение

- [ ] собраны 5-7 скриншотов ключевых проверок для completion-note;
- [ ] обновлена дата редакции в политике и согласии после финальных правок;
- [ ] клиенту отправлена completion-note (`completion-note.md`).

## Что специально НЕ покрыто этим QA

- проверка факта подачи уведомления в Роскомнадзор;
- проверка наличия внутренних локальных актов оператора;
- проверка договоров/поручений с обработчиками;
- аудит сроков хранения заявок в CRM;
- проверка локализации БД;
- юридическая проверка финальных формулировок.
