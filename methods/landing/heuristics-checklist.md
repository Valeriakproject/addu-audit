# Heuristics Checklist: детальная оценка лендинга по LIFT + CCD

Этот чеклист — основной инструмент эвристического аудита одностраничника. Пройди по всем блокам, но **фокус — на 5-8 крупных проблемах**, а не формальной галочке по каждому пункту.

Принцип: для каждого пункта задавай себе вопрос «**что бы сейчас остановило конкретного человека из целевой аудитории от целевого действия?**»

---

## 0. Blink Test — первые 5 секунд

Прежде чем идти по чеклисту — сымитируй «холодного» посетителя. Открой лендинг в первый раз, посмотри 5 секунд, закрой. Ответь:

- [ ] Что это за продукт/услуга?
- [ ] Для кого?
- [ ] Почему мне это может быть нужно?
- [ ] Что надо сделать?
- [ ] Вызывает ли это доверие?

Если на любой из вопросов ты не можешь ответить — это уже находка номер один.

## 1. LIFT Model — 6 факторов (WiderFunnel, Chris Goward)

Классическая CRO-линза. Каждый фактор = один подраздел чеклиста. Для каждого — оценка «сильно / слабо / нейтрально» со скриншотом.

### 1.1 Value Proposition (усилитель)

**Ключевой вопрос**: за 5 секунд понятно, какую *ценность* получит клиент?

- [ ] **H1 говорит о результате клиента**, а не о продукте? («Получите 100 заявок в месяц» > «CRM для малого бизнеса»)
- [ ] Подзаголовок уточняет: **для кого** + **за счёт чего** + **как быстро**?
- [ ] Есть **4-6 конкретных бенефитов** (цифры, сроки, результаты), а не абстрактные «быстро, качественно, надёжно»?
- [ ] Отличие от конкурентов явно сформулировано (если ниша конкурентная)?
- [ ] Hero-изображение **поддерживает** оффер, а не мешает (не стоковое фото рукопожатия)?

### 1.2 Relevance (усилитель) — **message match**

**Ключевой вопрос**: текст и визуал соответствуют источнику трафика и ожиданиям посетителя?

- [ ] Если трафик с **PPC** — H1 повторяет ключевой запрос объявления (или очень близко)?
- [ ] Если трафик с **таргета ВК/Telegram** — визуал и тон совпадают с креативом?
- [ ] Если трафик **холодный** — лендинг не предполагает, что посетитель уже знает о компании?
- [ ] Если трафик **тёплый/бренд** — наоборот, не разжёвывает очевидного?
- [ ] Если **сезонный** оффер — сезон заявлен явно (весна 2026, «к лету», «до 30 апреля»)?

### 1.3 Clarity (усилитель)

**Ключевой вопрос**: одна ясная мысль на экран, никакого жаргона без объяснения?

- [ ] H1 читается с первой попытки, без перечитывания?
- [ ] **Нет маркетингового жаргона** («инновационные решения», «синергия», «экосистема»)?
- [ ] **Нет технического жаргона** без объяснения (если аудитория не техническая)?
- [ ] Один блок = одна мысль (не пытается сказать 3 вещи сразу)?
- [ ] Визуальная иерархия ведёт взгляд по F/Z-паттерну — сначала главное, потом детали?
- [ ] Длинные списки разбиты буллетами, а не сплошным текстом?
- [ ] Короткие абзацы (2-4 строки), подзаголовки, сканируемость?

### 1.4 Distraction (барьер)

**Ключевой вопрос**: ничего не отвлекает от целевого действия?

- [ ] **Attention Ratio**: сколько ссылок и кнопок ведут в другие места? Идеал для PPC = 1:1 (один CTA).
- [ ] В шапке нет большого меню с ссылками на отдельные страницы (если лендинг рекламный)?
- [ ] Нет блоков, которые не работают на конверсию (избыточная «о компании», длинная история)?
- [ ] Всплывающие окна, попапы, чат не блокируют контент сразу после загрузки?
- [ ] Анимации, видео-фоны, параллакс не мешают читать текст?
- [ ] Нет ссылок на соцсети в шапке (они уводят)?

### 1.5 Urgency (усилитель)

**Ключевой вопрос**: есть ли причина действовать *сейчас*, а не «потом»?

- [ ] Есть **дедлайн** (дата окончания, обратный отсчёт) или ограничение (количество мест, бонусы первым N)?
- [ ] Срочность **правдоподобна** — не фейковые таймеры, которые сбрасываются при перезагрузке?
- [ ] Социальная динамика: «уже 247 человек записались», «осталось 3 места»?
- [ ] Если urgency искусственный — он отключён (лучше без urgency, чем с фейковым, это убивает доверие)?
- [ ] Для B2B — урgency через *упущенную возможность*, а не «скидка только сегодня»?

### 1.6 Anxiety (барьер)

**Ключевой вопрос**: сняты ли возражения, которые мешают нажать кнопку?

- [ ] **Цена** видна (или понятно, что бесплатно / без обязательств)?
- [ ] **Гарантии** сформулированы: возврат денег, бесплатная первая консультация, без автопродления?
- [ ] **Что будет после клика**? («Перезвоним в течение 15 минут», «Скачаете PDF», «Отправим на email»)
- [ ] **Privacy** — рядом с формой ссылка на политику и галочка 152-ФЗ?
- [ ] Нет ли агрессивных приёмов, которые вызывают подозрение («ПОСЛЕДНИЙ ШАНС!!!», «СЕКРЕТНАЯ МЕТОДИКА»)?
- [ ] Логотипы клиентов/партнёров — реальные, известные аудитории?
- [ ] Отзывы — с фото, фамилиями, ссылками на соцсети (а не стоковые картинки с именами «Иван И.»)?
- [ ] Юр. реквизиты в футере (ИП/ООО, ИНН, адрес)?

## 2. Conversion-Centered Design — 7 принципов (Oli Gardner, Unbounce)

Структурные правила именно для лендингов (не для сайтов).

### 2.1 Attention (один фокус)

- [ ] **Attention Ratio 1:1** для PPC-лендинга: посчитай все ссылки и кликабельные элементы. Должна быть одна цель.
- [ ] Для органического/брендового лендинга допустимо 1:N, но N ≤ 5.
- [ ] Главный CTA заметнее всего остального (цвет, размер, контраст).

### 2.2 Context

- [ ] Контекст объявления/источника соответствует контексту страницы (цвет, визуал, тон).
- [ ] Если лендинг адресован конкретному сегменту (PPC по запросу X) — на странице это отражено.

### 2.3 Clarity

(перекрывается с LIFT Clarity, см. выше)

### 2.4 Congruence

- [ ] Все элементы работают на одну цель: hero обещает → proof подтверждает → form закрывает.
- [ ] Нет противоречий: «бесплатная консультация» в hero и «от 15 000 ₽» в price-блоке.

### 2.5 Credibility

- [ ] **Логотипы клиентов** — реальные, известные, с согласием на использование.
- [ ] **Отзывы** — 3-5 штук, с фото, фамилиями, ролью/компанией. В идеале — видео или ссылка на соцсети.
- [ ] **Кейсы** — конкретные цифры («увеличили выручку X на 43%», а не «значительно улучшили показатели»).
- [ ] **Сертификаты, награды, упоминания в СМИ** (если есть и аудитория их знает).
- [ ] **Команда** — фото и роли ключевых людей (для B2B и премиум-услуг критично).
- [ ] **Годы на рынке / количество клиентов** — социальное доказательство масштаба.

### 2.6 Closing — форма и CTA

- [ ] **Минимум полей** — только то, что реально нужно для следующего шага. Имя + телефон. Иногда только телефон.
- [ ] Не требуется **регистрация** или создание пароля на лендинге.
- [ ] **Inline-валидация** — красный = ошибка сразу, а не после submit.
- [ ] **Автозаполнение** работает (правильные `autocomplete` атрибуты, `type="tel"` / `type="email"`).
- [ ] **Кнопка CTA — выгодный текст**, а не «Отправить». «Получить расчёт», «Записаться на бесплатный аудит», «Скачать PDF».
- [ ] **Privacy note** под формой + галочка 152-ФЗ (обязательно для РФ).
- [ ] **Что будет после** — явно сказано («перезвоним в течение 15 минут», «письмо придёт на указанный email»).

### 2.7 Continuance — что после конверсии

- [ ] После отправки формы — **thank you page** с инструкциями, а не просто «Спасибо».
- [ ] На thank you — что клиент получит, когда, от кого, как подготовиться.
- [ ] Трекинг конверсии настроен (Метрика цель + пиксель рекламной системы).

## 3. Структурные блоки лендинга — чеклист по секциям

### 3.1 Hero (первый экран)

- [ ] H1 — результат + аудитория (см. 1.1)
- [ ] Подзаголовок — уточнение
- [ ] CTA в hero (главная кнопка или форма лид-магнита)
- [ ] Hero-изображение поддерживает оффер (продукт, результат, целевая ситуация)
- [ ] На мобильной — hero помещается в первый экран и не требует скролла до CTA

### 3.2 Proof — социальное доказательство

- [ ] Сразу после hero (или на втором экране) — логотипы клиентов / цифры / соцдок
- [ ] Не абстрактные («лучшие в отрасли»), а конкретные («более 200 клиентов с 2018 года»)

### 3.3 Problem / Agitation (для холодного трафика)

- [ ] Описана проблема аудитории — её болит
- [ ] Не перебор с pain-амплификацией (для B2B это раздражает)
- [ ] Решение — плавный переход к продукту

### 3.4 Solution / Benefits

- [ ] 4-6 бенефитов с иконками и краткими пояснениями
- [ ] Каждый бенефит = результат клиента, а не фича продукта
- [ ] Формат «Фича → Выгода» («Чат-бот → Отвечает клиентам за секунды 24/7»)

### 3.5 How it works / Process

- [ ] 3-5 шагов, понятных и с минимальными действиями со стороны клиента
- [ ] Снимает тревогу «сколько мне придётся сделать»

### 3.6 Pricing / Offer

- [ ] Цена видна (либо явно заявлено «бесплатно» / «по запросу»)
- [ ] Если тарифы — рекомендованный выделен визуально
- [ ] Что включено в каждый тариф — буллетами
- [ ] Рассрочка/оплата частями — если релевантно нише (курсы, дорогие услуги)

### 3.7 Testimonials / Cases

- [ ] 3-5 отзывов с фото, фамилиями, ролью
- [ ] В идеале — кейсы с измеримым результатом (цифры)
- [ ] Ротация/карусель работает и на мобильной

### 3.8 FAQ

- [ ] 5-8 реальных возражений, а не «Что такое наш продукт?»
- [ ] Ответы снимают тревогу, не уклоняются
- [ ] Аккордеон работает на мобильной

### 3.9 Final CTA

- [ ] Повторение главного CTA перед футером
- [ ] Перед ним — финальный аргумент (гарантия, usp, социальное доказательство)

### 3.10 Футер

- [ ] Юр. реквизиты (для РФ критично)
- [ ] Контакты (телефон, email, адрес)
- [ ] Ссылки на политику конфиденциальности и оферту
- [ ] Мессенджеры и соцсети (если есть)

## 4. Mobile-specific (65-75% трафика в РФ)

- [ ] **Viewport** настроен корректно, нет горизонтального скролла
- [ ] Тап-таргеты **≥ 44×44 px** (Apple HIG), между ними расстояние
- [ ] Шрифт **≥ 14-16 px** без зума
- [ ] **Sticky CTA** внизу экрана на скролле (не обязательно, но сильно повышает CR)
- [ ] Формы — правильные типы клавиатур (`tel`, `email`, `number`)
- [ ] Попапы/баннеры не блокируют контент при загрузке (Google штрафует)
- [ ] Hero помещается в первый экран (или CTA виден без скролла)
- [ ] Скорость загрузки на 4G — ≤ 3 секунды до интерактивности

---

## 5. Trust — специфика для РФ

- [ ] **Юр. реквизиты в футере**: ИП/ООО, ИНН, иногда ОГРН
- [ ] **Политика конфиденциальности** — ссылка из футера и рядом с формой
- [ ] **152-ФЗ**: галочка «Согласен на обработку персональных данных» рядом с кнопкой формы
- [ ] **Cookie-баннер** с подтверждением согласия (не принудительный)
- [ ] **Реальный адрес** офиса или местонахождения (не «Москва»)
- [ ] **Реальный телефон** (городской +7 495 / +7 812 повышает доверие в B2B)
- [ ] **Мессенджеры** в шапке/футере — Telegram, WhatsApp (в РФ это ожидаемо)
- [ ] **Отзывы с реальных платформ** — Яндекс, 2ГИС, Отзовик (интеграция предпочтительнее скриншотов)
- [ ] **Фото команды/офиса** для B2B и премиум-услуг

## 6. Техническая гигиена (проверяется в Шаге 3 workflow)

### 6.1 Core Web Vitals
- [ ] **LCP** < 2.5 сек (Largest Contentful Paint)
- [ ] **CLS** < 0.1 (Cumulative Layout Shift)
- [ ] **INP** < 200 мс (Interaction to Next Paint)

### 6.2 Производительность
- [ ] Размер страницы ≤ 3 MB (для 4G в регионах)
- [ ] Изображения: WebP, lazy load, корректные размеры
- [ ] Нет блокирующих скриптов в head
- [ ] CDN для статики

### 6.3 SEO-гигиена (через squirrelscan)
- [ ] Title и description — уникальные, релевантные
- [ ] Один H1 на странице
- [ ] Микроразметка Schema.org (Service, Organization, FAQ)
- [ ] Нет broken links (4xx/5xx)
- [ ] Нет JS-ошибок в консоли
- [ ] SSL валидный, HTTPS работает

### 6.4 Трекинг
- [ ] Яндекс.Метрика установлена
- [ ] Цели на отправку формы настроены
- [ ] Вебвизор, карта скроллинга, карта кликов — включены
- [ ] Пиксели рекламных систем (если есть реклама) — на месте
- [ ] GTM (если используется) — без ошибок

## Как использовать этот чеклист

1. **Не пробегай формально** — каждый раздел не обязан дать пункт в отчёт.
2. **Ищи «горячие точки»** — места, где сразу видно, что пользователь уйдёт.
3. **Смотри в контексте источника трафика** — для PPC-лендинга критичен Attention Ratio, для SEO-лендинга — реже.
4. **Проверяй мобильную версию отдельно** — часто там в разы хуже, чем в desktop.
5. **Записывай скриншоты** — они усилят отчёт.
6. **Всегда держи в голове: "кто этот посетитель и что его остановит?"** — чеклист должен служить этому вопросу, а не наоборот.

Из сотен потенциальных пунктов отбирай **5-8 самых больных** и раскрывай их глубоко в отчёте.
