# Правила ADDU для аудитов (добавить к скиллам)

## 1. Скидка 30% в аудитах по 152-ФЗ

В аудитах по 152-ФЗ даём ограниченное предложение: **скидка 30% при оплате в течение 3 рабочих
дней**. Это разовое условие для тех, кто решает сразу. Кто не успел, покупает те же работы по
полной стоимости. Скидка не продлевается и не повторяется.

Как считать: фиксированную стоимость по смете умножить на 0,7 и округлить до целых рублей.
Пример: 11 250 ₽ → 7 875 ₽.

Как показывать в отчёте, отдельными строками под итогом сметы:

```
Стоимость работ: 11 250 ₽
При оплате до 12.09.2026: 7 875 ₽
```

Дату писать конкретным числом (дата аудита плюс 3 рабочих дня), а не формулировкой «в течение трёх
дней». Полную стоимость не убирать и не заменять скидочной: клиент должен видеть обе цифры, иначе
скидка не читается как выгода.

В письме про скидку одна строка, отдельного абзаца и слова «акция» не надо.

Скидка действует только на 152-ФЗ. На технический, маркетинговый и SEO аудиты не распространяется.

Аудит отправлять клиенту в тот же день, когда он сделан. Если отчёт пролежал пару дней, дата в нём
уже неверная, надо пересчитать.

### Готовая разметка, вставлять как есть

Не придумывай оформление сам. В клиентском HTML-отчёте блок со скидкой ставится сразу под блоком
с полной стоимостью. Скопируй этот код и подставь свои цифры и дату:

```html
<div class="total">
  <span>Фиксированная стоимость работ по перечисленному объёму</span>
  <strong>7 500 ₽</strong>
</div>
<div class="total discount">
  <span><strong>При оплате до 10 сентября 2026</strong><br><span class="muted" style="font-size:11px;">Разовое условие для тех, кто решает сразу</span></span>
  <strong>5 250 ₽</strong>
</div>
```

В блок стилей отчёта (тег `style` в шапке) добавь две строки, иначе скидка будет выглядеть как
обычный жёлтый блок:

```css
.total.discount { border-color: #bcdcc9; background: #eef7f1; }
.total.discount strong { color: #2d6b57; }
```

В строку про сроки под блоком допиши: «После {дата} работы выполняются по полной стоимости.»

## 2. Формат выдачи клиенту

Правило простое: **всё, что документ, — файлом. Всё, что витрина, — ссылкой.**

| Работа | Что отдаём | Как |
|---|---|---|
| Аудит по 152-ФЗ | **PDF-файл** | Не ссылку. Перед отправкой перечитать, бывают неточности |
| Технический аудит | **PDF-файл** | Не ссылку |
| **Маркетинговое исследование** | **PDF-файл** | Не публикуется на case.addu.ru, отдаётся вложением |
| **Маркетинговый аудит** | **Ссылку** | Публикуется на case.addu.ru |
| SEO и ИИ-аудит | Ссылку | Публикуется на case.addu.ru, обычно в составе пакета |

Как получить PDF: ассистент делает отчёт веб-страницей, дальше открыть в браузере и **Печать →
Сохранить как PDF** (A4, с фоном и графикой), либо попросить «сделай из этого PDF». Печатные стили
в шаблонах прописаны: липкое меню скрывается, разрывы страниц расставлены. Проверить, что PDF
совпадает с веб-версией.

## 3. Публикация на case.addu.ru

Клиентские версии маркетинговых работ **не отправляем файлом** — публикуем на
**https://case.addu.ru/** и даём ссылку.

### Каждый тип работы в свою подпапку

Это важно: раньше всё писалось в `case.addu.ru/{домен}/`, и следующая работа затирала предыдущую.

| Что сделали | Куда публикуем | Ссылка клиенту |
|---|---|---|
| Маркетинговый аудит сайта, магазина, лендинга | `{домен}/marketing/` | `https://case.addu.ru/{домен}/marketing/` |
| SEO-аудит | `{домен}/seo/` | `https://case.addu.ru/{домен}/seo/` |
| ИИ-аудит, видимость в нейросетях | `{домен}/ai-seo/` | `https://case.addu.ru/{домен}/ai-seo/` |

**Маркетинговое исследование сюда не публикуется** — оно уходит клиенту файлом.

**Никогда не публиковать в корень `{домен}/`** и не перезаписывать чужую подпапку. Если по этому
домену уже что-то лежит, это работа другого типа, её трогать нельзя.

Аудит 152-ФЗ, технический аудит и маркетинговое исследование сюда не публикуются, они уходят клиенту файлом.

### Как загрузить

Файл отчёта называется `index.html` и кладётся внутрь подпапки:

```bash
curl -T "index.html" "ftp://USER:PASS@HOST/{домен}/{тип}/index.html"
```

Скриншоты, если они не встроены в base64, кладутся рядом в `{домен}/{тип}/screens/`.

`USER` / `PASS` / `HOST` — из `publish-credentials.local.md`, пароль у пользователя не запрашивать.

**Проверь ссылку в браузере, прежде чем отдать её клиенту.** Публикация не считается выполненной,
пока страница не открылась.

Если FTP не отвечает и соединение виснет по таймауту, дело в VPN: хостинг российский, через
иностранный адрес он не пускает. Выключить VPN на время загрузки либо загрузить через Cyberduck.

## 4. Доступы (заполнить один раз)

FTP-доступ к case.addu.ru тебе выдаст **Лера лично** (в переписке эти данные не пересылаются).
Создай рядом с этим файлом файл `publish-credentials.local.md` и впиши в него:

```
Host: <адрес>
User: <логин>
Password: <пароль>
```

Этот файл только у тебя на компьютере. **Никому не пересылай и на GitHub не заливай.**
