# Bitrix Technical Audit

Скилл для технического аудита сайта на 1С-Битрикс с упором на **продажу регулярной поддержки** (абонентское обслуживание addu.ru), а не разовой правки.

## Назначение и философия

Цель — показать клиенту, что сайт это **живая система** (заявки, корзина, каталог, формы, персональные данные), которой нужен регламент: обновления, безопасность, скорость, индексация, бэкапы, мониторинг. Не «у вас всё плохо», а «есть технический долг, который дешевле вести по регламенту, чем чинить после поломки».

Аудит делится на два контура:
1. **Внешний** — без доступа в админку/на сервер. Делается всегда, быстро, перед созвоном.
2. **Внутренний** — в админке 1С-Битрикс. Делается при наличии доступа; часть внешних выводов это **гипотезы**, которые подтверждаются только внутри.

## Когда использовать

- Технический аудит магазина / корпоративного сайта / каталога на Битрикс.
- Подготовка к созвону по продаже поддержки.
- Проверка после смены подрядчика, хостинга, крупного обновления.

Для конверсии/маркетинга — другие скиллы (см. description).

## Требования

- **squirrelscan CLI** — команда `squirrel` (npm-пакет `squirrelscan`, установлен глобально, v0.0.81). Быстрый скан 230+ правил (SEO, meta, security, broken links, performance). Фолбэк без глобальной установки — `npx squirrelscan audit <url>`; либо старый бинарь `tools/squirrel.exe` (v0.0.38, устаревший, держим только на случай offline).
- **Chrome DevTools MCP / Playwright MCP** — ручные HTTP-проверки, заголовки, скриншоты, Core Web Vitals.
- **Доступ в админку 1С-Битрикс** — опционально, для внутреннего контура.

## Workflow

### Шаг 0: Контекст
Уточни: URL; есть ли доступ в админку; тип сайта (магазин/корпоративный/каталог/лендинг); цель (продажа поддержки / запуск / безопасность / SEO / скорость).

### Шаг 1: Внешняя разведка без доступа
**Прочитай `references/external-recon-checklist.md`.** Прогон squirrelscan + ручные проверки:
признаки Битрикса, HTTP→HTTPS, www/index.php дубли, robots.txt, sitemap.xml, 404, canonical,
title/description, security headers, cookie flags, вес HTML/ресурсов, кэширование, старый фронт-стек,
публичность `/bitrix/admin/`. Результат: список внешне подтверждённых проблем + список гипотез для админки.

```
squirrel audit <url>   # быстрый скан, сохрани вывод в audits/{slug}-assets/
```

### Шаг 2: Внутренний аудит в админке (если есть доступ)
**Прочитай `references/admin-panel-checklist.md`** (блоки A–F): обновления и лицензия, Проверка системы,
Производительность, Проактивная защита, бэкапы, регресс интернет-магазина.

### Шаг 3: Регресс бизнес-функций
Прогони сценарии: заявка с каждой формы, заказ через корзину, купить в один клик, запрос цены, поиск,
фильтр каталога, карточка товара, письмо администратору, письмо клиенту, цели аналитики.

### Шаг 4: Приоритизация
Раздели находки на: **Срочно** (1-2 недели) / **Планово** (1 месяц) / **Регулярно** (каждый месяц).

### Шаг 5: Коммерческая упаковка
**Прочитай `references/commercial-packaging.md`.** Переведи каждую техпроблему в бизнес-эффект,
подготовь скрипт разговора, привяжи к тарифам поддержки.
**Тарифы — из `../assets/tariffs.md`** (не выдумывать).

### Шаг 6: Генерация отчёта

> **Куда писать результат.** Единый корень для всех аудитов:
> `audits/{domain}/tech/` (где `{domain}` — домен в ASCII с точками,
> напр. `18ga.ru`, `pazlypofoto.rf`). Папку создать, если её нет.

- **Рабочий черновик (Markdown):** `audits/{domain}/tech/{YYYY-MM-DD}-bitrix-tech-audit.md` —
  источник правды, база наработок. Сырые данные (squirrel XML, скриншоты) —
  в `audits/{domain}/tech/_assets/`.
- **Клиентская выдача (HTML):** самодостаточный HTML в едином дизайне.
  **Обязательно прочитай `../assets/design-system.md`**, скопируй `../assets/base-template.html`
  в `audits/{domain}/tech/index.html`, перенеси данные в JS-массивы. Вкладки: Обзор / Внешние находки /
  Чек-лист админки / План работ / Тарифы. Логотип встраивать base64 (НЕ относительным путём — иначе
  отвалится при деплое). Открой результат в браузере и проверь все вкладки.
- **Формат для клиента — PDF, не HTML.** После сборки `index.html` экспортируй его в PDF так, чтобы
  PDF визуально не отличался от HTML (печать A4 из браузера, фон/цвета включены). Клиенту отправляем PDF.
  На case.addu.ru технический аудит НЕ публикуется — публикация на case.addu.ru только для маркетинговых аудитов.

## Структура скилла

```
bitrix-technical-audit/
├── SKILL.md
├── references/
│   ├── external-recon-checklist.md   # внешний контур (squirrelscan + HTTP/SEO/security)
│   ├── admin-panel-checklist.md      # внутренний контур (блоки A–F)
│   └── commercial-packaging.md       # скрипт продажи + перевод в бизнес-эффект + приоритизация
├── tools/squirrel.exe                # старый бинарь squirrelscan (offline-фолбэк; основной путь — npm `squirrel`)
└── references/                        # чек-листы

Результаты НЕ хранятся в папке скилла. Всё пишется в единый корень:
audits/{domain}/tech/
├── {YYYY-MM-DD}-bitrix-tech-audit.md   # MD-черновик (источник правды)
├── index.html                          # клиентский HTML-deliverable
└── _assets/                            # squirrel XML, скриншоты (сырые данные)
```
