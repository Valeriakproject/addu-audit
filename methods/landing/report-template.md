**Объём**: 5-10 страниц (не больше). Лендинг — это короткий продукт, и отчёт должен быть такой же. Раздутый отчёт на 30 страниц клиент не читает.

## 4. Quick Wins — внедрить за 1-2 недели

### 🔥 Находка #1: H1 не о результате клиента

**Приоритет**: Критично (Impact 5/5, Effort 1/5)
**Фактор**: LIFT → Value Proposition (вес ×3 по MECLABS)
**Часы работы**: 1-2 часа

**Что сейчас:**

Текущий H1: *«Маркетинговое агентство полного цикла»*

Проблема в том, что посетитель за 5 секунд не понимает, **что он получит**. H1 описывает, *чем* является компания, а не *что* она даст клиенту.

**Почему это проблема:**

По LIFT Model ценностное предложение — главный фактор усиления конверсии (вес ×3 по MECLABS). 70% посетителей решают «оставаться или уходить» за первые 5-10 секунд (Nielsen Norman Group). Если за это время они не видят выгоду — уходят.

Для PPC-трафика это критично вдвойне: посетитель пришёл с конкретным запросом и ожидает быстрый ответ.

**Гипотеза:**

Если заменить H1 на формат **«[Результат] [за счёт чего] [для кого]»**, конверсия в заявку вырастет на 15-25% (типичный эффект улучшения value prop по кейсам CXL).

Варианты H1 для A/B теста:
- *«Приведём 50+ горячих заявок в месяц вашей B2B-компании за счёт связки Директ + лендинг»*
- *«Запустим рекламу с оплатой за результат: 50+ заявок в месяц или вернём бюджет»*

**Что сделать:**
1. Переписать H1 по формуле «Результат + за счёт чего + для кого» (1 час)
2. Добавить подзаголовок с уточнением «Работаем с B2B-компаниями с оборотом от X, средний срок до первых заявок — 14 дней» (1 час)
3. Запустить A/B тест в Яндекс.Метрика или через Google Optimize (отдельная работа, если есть трафик)

### 🔥 Находка #2: Нет message match с Яндекс.Директ

**Приоритет**: Критично (Impact 5/5, Effort 2/5)
**Фактор**: LIFT → Relevance (вес ×4 по MECLABS — Motivation)
**Часы работы**: 4-6 часов

**Что сейчас:**

Посмотрели топ-5 рекламных объявлений клиента в Директ. По ключу *«разработка лендинга на tilda»* объявление обещает «Разработку лендинга на Tilda за 5 дней». На лендинге в H1 — обобщённое «Маркетинговое агентство полного цикла».

**Почему это проблема:**

Message match — одна из самых недооценённых тем в российском PPC. По данным Unbounce, отсутствие совпадения между объявлением и лендингом снижает конверсию на 30-50%. Пользователь с конкретным запросом (Tilda, 5 дней) получает обобщённый оффер и уходит.

**Гипотеза:**

Если создать **отдельные версии лендинга под 2-3 основных кластера ключей** с уникальным H1 и hero-секцией, конверсия из PPC вырастет на 20-40%.

**Что сделать:**
1. Проанализировать топ-20 ключей в Директе, сгруппировать в 2-3 кластера (2 часа)
2. Создать 2-3 версии лендинга на Tilda (дубли + изменение H1 + hero-текст) (3-4 часа)
3. Настроить UTM-метки для разных кластеров → свои лендинги в Директе

### ⚠️ Находка #3: Нет 152-ФЗ согласия на форме

**Приоритет**: Важно (Impact 4/5, Effort 1/5)
**Фактор**: LIFT → Anxiety + юридический риск
**Часы работы**: 2 часа

**Что сейчас:**

Форма заявки содержит поля «Имя» и «Телефон», но:
1. Нет галочки «Согласен на обработку персональных данных»
2. Нет ссылки на политику конфиденциальности
3. Самой политики на сайте нет

**Почему это проблема:**

152-ФЗ требует явного согласия на ОПД. Отсутствие — юридический риск (штрафы Роскомнадзора, жалобы пользователей, блокировка рекламы). Также это сигнал «временной компании» для осознанной аудитории — снижает доверие.

**Гипотеза:**

Добавление галочки 152-ФЗ и политики конфиденциальности:
1. Уберёт юридический риск
2. Повысит доверие (особенно в B2B) — ожидаемый рост CR на 3-7%

**Что сделать:**
1. Создать страницу политики конфиденциальности (шаблон + реквизиты) — 1 час
2. Добавить галочку под формой с текстом и ссылкой — 0.5 часа
3. Проверить, что галочка НЕ отмечена по умолчанию (требование ФЗ) — 0.5 часа

## Советы по оформлению Markdown-отчёта

1. **Структура заголовков** — строгая иерархия H1 → H2 → H3. Один H1 = название отчёта, H2 = разделы 1-9, H3 = находки. Это даёт корректное оглавление при конвертации в PDF.
2. **Таблицы** — активно используй pipe-tables для scorecard и технических метрик.
3. **Цитаты** (`>`) — для ключевых выводов TL;DR.
4. **Эмодзи приоритетов** (🔥 ⚠️ 💡) — допустимы как визуальные маркеры. Без фанатизма.
5. **Блоки находок** — единый шаблон: Приоритет / Фактор / Часы → «Что сейчас» → «Почему это проблема» → «Гипотеза» → «Что сделать».
6. **Скриншоты** — складывать в `audits/{client-slug}-assets/` и подключать относительно. Не вставлять base64.

### Почему структура именно такая

1. **TL;DR первым** — руководитель читает только его
2. **Scorecard** даёт картину целиком на одной таблице
3. **Quick Wins подробно**, чтобы клиент мог сразу внедрять
4. **Medium/Long-term коротко** — это для обсуждения, не для немедленного действия
5. **Технический раздел отдельно** — чтобы не мешал бизнес-находкам
6. **Следующие шаги** — закрывает отчёт действием, а не выводом

Если отчёт выглядит как «накидал на коленке» — клиент подумает: «ну и работа будет такой же». Если структура чёткая, таблицы читаемые, выводы однозначные — клиент **уже верит**, что подрядчик серьёзный.
