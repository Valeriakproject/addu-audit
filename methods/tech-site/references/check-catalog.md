# Каталог проверок технического аудита

Это полный список того, что проверяет скилл `site-tech-audit`, и каким движком. Используется как чек-лист: каждый пункт получает один из статусов `ok`, `manual_review`, `risk_flag`, `hard_fail`.

## Разделение движков

| Зона | SquirrelScan (CLI, статика) | chrome-devtools MCP (интерактив) | Итог |
|---|---|---|---|
| Битые ссылки / редиректы / HTTP-статусы | основной | подтверждает фактические 404 при клике | объединяем |
| Mixed-content, HTTPS/SSL, security-заголовки | да | подтверждает в network | объединяем |
| SEO: title/description/H1/canonical/OG, robots, sitemap | да | — | из squirrel |
| Картинки: alt, размеры, битые `src` | да | подтверждает битые при рендере | объединяем |
| Скорость / Core Web Vitals | оценка | `lighthouse_audit` (реальный прогон) | Lighthouse приоритетнее |
| Доступность (a11y) | правила | `lighthouse_audit` | объединяем |
| **Кликабельность всех кнопок/ссылок** | нет | snapshot → клик каждого → наблюдение | наш интерактив |
| **Открытие модалок/попапов** | нет | да | наш интерактив |
| **Обвязка форм (без сабмита)** | нет | да | наш интерактив |
| **JS-ошибки в рантайме** | нет | `list_console_messages` | наш интерактив |
| **Упавшие сетевые запросы** | частично | `list_network_requests` | наш интерактив |
| **Мобильный рендер / tap-targets / скриншоты** | правила | `emulate`/`resize` + `take_screenshot` | объединяем |
| **Кодировка / mojibake** | правило charset | визуально на скриншоте | объединяем |
| Реальная доставка заявки в CRM, нагрузка, бэкенд | нет | нет (не сабмитим) | `manual_review` |

## Категории проверок (детально)

### 1. Доступность страниц и ссылки
- Все внутренние ссылки отдают 200 (нет 404/410/5xx).
- Нет цепочек редиректов и битых редиректов.
- Внешние ссылки живы (или помечены как требующие проверки).
- Нет ссылок на `http://` ресурсы, ведущих в никуда.
- Robots.txt и sitemap.xml присутствуют и валидны.

### 2. Кнопки и интерактив (ядро аудита)
- Каждая видимая кнопка/ссылка реагирует на клик (навигация, модалка, действие).
- Нет «мёртвых» кнопок (`href="#"`, `onclick`, который падает или ничего не делает).
- Модальные окна открываются и закрываются.
- Слайдеры/табы/аккордеоны/галереи работают.
- Меню (в т.ч. выпадающие) раскрываются.

### 3. Формы (только обвязка, без отправки)
- Поля присутствуют и редактируемы.
- Клиентская валидация срабатывает (required, формат телефона/email).
- Есть защита от спама (reCAPTCHA/капча), если ожидается.
- `action`-эндпоинт существует и отвечает (HEAD/GET, **без реального сабмита**).
- Нет JS-ошибок при взаимодействии с формой.

### 4. JavaScript и сеть
- В консоли нет ошибок уровня `error` при загрузке и кликах.
- Нет упавших сетевых запросов (404 ассетов, CORS, blocked, ERR_*).
- Нет смешанного контента (http-ресурсы на странице).

### 5. Скорость и Core Web Vitals
- Lighthouse Performance score.
- LCP, CLS, INP/TBT в приемлемых рамках.
- Нет тяжёлых неоптимизированных картинок, блокирующих скриптов.

### 6. Мобильная версия
- Наличие корректного `viewport`.
- Контент не уезжает за экран, нет горизонтального скролла.
- Tap-targets достаточного размера.
- Скриншот мобильной версии без визуальных поломок.

### 7. Кодировка и техническое здоровье
- Корректная отдача charset (для allprint — windows-1251; mojibake = проблема).
- Валидный `<!doctype>`, нет грубых ошибок разметки, ломающих рендер.
- Favicon отдаётся.

### 8. Безопасность передачи (видимая часть)
- HTTPS доступен и валиден; редирект HTTP→HTTPS.
- Security-заголовки (CSP, HSTS) — как `manual_review`/`risk_flag`, не как пентест.

## Маппинг severity

- `hard_fail` — ломает работу для пользователя: страница не открывается (5xx), ключевая кнопка/форма не работает, JS-ошибка ломает функционал, сайт без HTTPS целиком.
- `risk_flag` — заметный дефект, который надо чинить: битые ссылки/картинки, mixed-content, медленная загрузка, поломки на мобильном, mojibake.
- `manual_review` — нельзя подтвердить из открытой части: реальная доставка заявок в CRM, бэкенд-ошибки, нагрузка, кросс-браузерность вне Chrome.
- `ok` — проверено, проблем нет.

## Границы (не выдумывать)
- Если сайт недоступен — честно указать, не генерировать находки.
- Не называть это пентестом или гарантией безопасности.
- Severity ставить по фактическому наблюдению, а не по предположению.
