# Estimate Rules — технический аудит

Ставка: `2500 ₽/час`. Внутри округляем до 15 минут, клиенту даём **одну фиксированную цену**, не диапазон.

## Типовые работы

| Работа | Оценка |
|---|---:|
| Починка одной битой ссылки / редиректа | 15 мин |
| Массовая правка битых ссылок (по списку, один тип) | 30–60 мин |
| Устранение mixed-content (скрипт/картинка по http) | 15–30 мин |
| Замена/починка одной битой картинки | 15 мин |
| «Мёртвая» кнопка / сломанный JS-обработчик | 15–30 мин за элемент |
| Починка модалки / слайдера / таба | 30 мин за компонент |
| Починка обвязки формы (валидация, action, reCAPTCHA) | 30 мин за форму |
| Настройка HTTPS + редирект HTTP→HTTPS | 30–60 мин (сертификат отдельно) |
| Исправление кодировки/charset (mojibake, корректная отдача) | 30–60 мин |
| Фикс мобильной вёрстки одной зоны / tap-targets | 30–60 мин |
| **Полный ретрофит адаптива на неадаптивном макете** | **14–18 ч** (см. ниже) |
| Заголовки безопасности на сервере (HSTS, CSP, X-Frame-Options, X-Content-Type-Options) | 1,5 ч |
| Флаги cookie (Secure, HttpOnly, SameSite) | 30 мин |
| Обновление устаревшей библиотеки с регрессом интерактива | 2 ч |
| robots.txt и canonical | 1 ч |
| Защита форм от робота | 1 ч за форму |
| Яндекс.Метрика и цели на формы | 2 ч |
| Оптимизация скорости (сжатие/ленивые картинки, кэш, минификация) | от 1 ч |
| Обновление устаревшей JS-библиотеки, ломающей функционал | от 1 ч |
| Повторная проверка после фиксов | 30 мин |
| Подготовка финального отчёта | 30 мин |

## Нет адаптива вообще — это не «фикс мобильной вёрстки»

Самая дорогая ошибка в оценке. Если `meta viewport` отсутствует, строка «фикс мобильной вёрстки
одной зоны, 30–60 минут» **не применяется**: чинить нужно не зону, а весь шаблон. Добавить один тег
без переверстки стилей делает страницу хуже, чем она была.

Считать по строкам, а не одной цифрой:

| Работа | Часы |
|---|---:|
| Шапка: логотип, контакты, кнопки | 2,0–2,5 |
| Горизонтальное меню → мобильное | 2,0 |
| Двухколоночная сетка «сайдбар + контент» → одна колонка | 3,0 |
| Контентные блоки, баннеры, изображения | 2,0–2,5 |
| Таблицы (каталог, реестр, прайс) | 1,5 |
| Всплывающие формы | 1,5 |
| Cookie-баннер | 0,5 |
| Подвал | 1,0 |
| Проверка на трёх разрешениях | 1,5 |

Проверка себя: если в смете строка «мобильный шаблон» одна и меньше 10 часов — оценка неверная.

## Разбивка на пакеты

Объём больше ~10 часов подавать не одним счётом, а пакетами, которые покупаются по отдельности
и в любом порядке:

1. **Срочное** — то, что теряет обращения прямо сейчас: битые контакты, 404 на ключевых страницах,
   мёртвые кнопки. Держать дешёвым, 2–3 часа: это быстрое «да», после которого проще продать остальное.
2. **Крупная работа** — обычно адаптив.
3. **Безопасность и техдолг.**

Повторную проверку выносить отдельной строкой, всегда.
Итог по всем пакетам показывать отдельной строкой.

## Правила расчёта
- 15 мин = 0.25 ч, 30 мин = 0.5 ч; умножаем на 2500 ₽/ч.
- В клиентской оферте — точные часы и точные рубли, одна сумма.
- Если остаётся неопределённость — округляем вверх до ближайшие 0.5 ч.
- Один повторяющийся шаблон (напр. одна форма на многих страницах) считаем один раз + время на ретест.
- Технически разные элементы считаем отдельно.
- Не писать в клиентской оферте «уточним после доступа к CMS» — оферта на перечисленный объём.

## Внутренние ориентиры

Это ориентиры, а не потолок. Если находки дают больше часов — ставим больше часов.

- мелкие точечные правки (1–3 находки): 2–4 ч / 5 000–10 000 ₽;
- средний набор (битые ссылки + mixed-content + точечная мобилка): 4–7 ч / 10 000–17 500 ₽;
- крупный технический долг (HTTPS + кодировка + скорость + куча битых элементов): 7–12 ч / 17 500–30 000 ₽;
- **сайт без адаптива + техдолг: 25–30 ч / 62 500–75 000 ₽.** Один только ретрофит адаптива это
  14–18 ч, и он почти всегда идёт вместе с накопленными мелочами.

## Что НЕ входит в технический бюджет (выносим отдельно)
- покупка SSL-сертификата и доступ к серверу/хостингу;
- переработка дизайна / редизайн;
- доработка бэкенда и интеграций с CRM;
- нагрузочное тестирование;
- работы по 152-ФЗ (отдельный аудит `addu-152fz-audit`).

Помечать такие пункты как `требует отдельной оценки / доступа`.
