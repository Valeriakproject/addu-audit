# Публикация маркетингового аудита на case.addu.ru

Клиентскую версию **маркетингового** аудита (CRO / интернет-магазин / лендинг) ВСЕГДА
публикуем на нашем ресурсе **https://case.addu.ru/** и отправляем клиенту ссылку, а не файл.
Технический аудит и 152-ФЗ сюда НЕ публикуются — по ним клиенту уходит PDF (см. ИНСТРУКЦИЮ).

## Правило

- После готовности клиентского `index.html` — загрузи его (и папку `screens/`, если
  скриншоты не встроены в base64) по FTP в папку с именем `{domain}` (домен клиента).
- Итоговая ссылка для клиента: `https://case.addu.ru/{domain}/`.
- **Пароль не запрашивай у пользователя.** Реквизиты доступа лежат локально — прочитай их из
  `_audit-shared/publish-credentials.local.md` и используй.
- Проверь, что `https://case.addu.ru/{domain}/` открывается, прежде чем давать ссылку клиенту.

## Как загрузить (Windows, curl)

```bash
# один файл
curl -T "index.html" "ftp://USER:PASS@HOST/{domain}/index.html"
# папка со скриншотами (если не base64) — по файлу
curl -T "screens/home.png" "ftp://USER:PASS@HOST/{domain}/screens/home.png"
```

USER / PASS / HOST — из `publish-credentials.local.md`. Если curl не создаёт вложенную
папку `{domain}` автоматически — создать её заранее (WinSCP / lftp) или загрузить в уже
существующую структуру.

## Первый запуск (подтвердить один раз)

Структуру веб-корня FTP подтвердить один раз: файлы кладутся в корень FTP или в подпапку
(`www/`, `public_html/`, `htdocs/`) так, чтобы отдавалось на `case.addu.ru/{domain}/`.
После подтверждения — работать по отлаженной схеме, не переспрашивая.

## Безопасность

Файл с доступами (`publish-credentials.local.md`) — **локальный**, в репозиторий и на GitHub
не попадает (см. `.gitignore`). Сам этот файл (`publish-case-addu.md`) пароль не содержит —
его можно хранить в репозитории.
