# Правила адаптации анкеты под результаты аудита

Эти правила превращают шаблон вопросов из `question-bank.md` в конкретную анкету для клиента. Цель — не задать клиенту лишнего.

## Базовые блоки (всегда включать)

Эти вопросы нужны всегда — без них нельзя выпустить даже минимальный пакет документов:

- Реквизиты оператора: тип юр.лица, наименование, ИНН, ОГРН/ОГРНИП, юр.адрес, почтовый адрес для обращений.
- Email для обращений по ПДн (с предзаполнением, если на сайте виден контактный email).
- Хостинг-провайдер сайта.
- Используются ли рекламные коммуникации (email, SMS, мессенджеры).
- Подавалось ли уведомление в Роскомнадзор (для пометки в notes-and-sources).
- Доступ к сайту: можно ли создать отдельного пользователя в админке.

## Условные блоки (включать только если…)

### Если в findings есть форма корзины / оформление заказа

Добавить блок:
- Платёжная система (Yookassa / CloudPayments / Тинькофф / иное).
- Куда уходят данные о заказах (CRM, 1С, email).
- Сроки хранения заказов (с подсказкой: «по бухучёту не менее 5 лет»).

Если корзины нет — этот блок не показываем.

### Если в findings есть форма регистрации / личный кабинет

Добавить блок:
- Какие функции в личном кабинете (история заказов, бонусы, иное).
- Есть ли возможность удалить учётную запись.

### Если в findings есть форма подписки на рассылку

Добавить блок:
- Какой сервис email-рассылок используется (если есть).
- Если ответ на главный вопрос «рекламные рассылки» = нет, спросить: «планируется ли в будущем?» — это влияет на наличие отдельного чекбокса в форме подписки.

### Если в findings найдена Яндекс.Метрика

Спросить:
- Подтвердите номер счётчика: {ID из findings} — или укажите актуальный.
- Используется ли Вебвизор / запись действий пользователя?

Если не найдена:
- Подключаете ли Яндекс.Метрику динамически (через GTM, модуль CMS)?
- Планируете ли подключать в ближайшее время?

### Если в findings найдены чат-виджеты / коллтрекинг / CRM-формы

Уточнить конкретные сервисы (JivoSite, Calltouch, Carrot Quest и т.д.) — нужно перечислить как обработчиков.

### Если в findings нет видимой формы доставки/самовывоза, но есть корзина

Спросить, какими службами доставки пользуетесь.

### Если CMS определена

Сформулировать вопрос по доступам конкретно под платформу:

- Bitrix: «Создайте пользователя в админке Bitrix с правами на редактирование страниц, шаблонов, веб-форм и `.htaccess`».
- Tilda: «Добавьте сотрудника в проект Tilda через официальный доступ к проекту, не присылайте пароль».
- WordPress: «Создайте пользователя с ролью Administrator (или Editor + плагины), не делитесь паролем главного аккаунта».
- Modx / иное: «Создайте отдельного пользователя CMS с правами на редактирование шаблонов и страниц».
- Самописная CMS: «Дайте контакт разработчика или доступ к репозиторию, либо опишите, как мы можем внести правки».

## Условия для опциональных вопросов

Если в банке вопросов помечено «опционально» — задавать только когда:
- ответ повлияет на текст документа (например, наличие IP-телефонии → строка в таблице обработчиков);
- ответ нельзя получить позже без задержки в работе;
- вопрос не дублирует другой.

## Сжатие текста

- Каждый блок открывать одной фразой контекста («Мы видим из аудита, что…») — не более 1 строки.
- Если у блока 1 вопрос — не делать заголовок, давать одним абзацем.
- Группировка в банке: «Реквизиты», «Сайт и бизнес», «Формы и заявки», «Маркетинг», «Аналитика и виджеты», «Хранение данных», «Доступы».
- Максимум 5 групп в финальной анкете. Если получилось больше — слить ближайшие.

## Тон

- Обращение на «Вы», деловое, тёплое.
- Без юр.жаргона типа «субъект ПДн», «локализация БД» — это пугает.
- Допустима фраза «не знаю» как валидный ответ — подскажем.
- Закрывать письмо коротким финалом: «Когда ответите — сразу запускаем работы и пришлём готовые документы на согласование».
