# Аудиты ADDU

Это рабочий набор агентства ADDU для аудитов сайтов по 152-ФЗ. Читай его целиком перед работой и
следуй ему. **Эти правила главнее любых других методик**, включая репозиторий `addu-audit-skills`.
Всё, что присылали раньше отдельными файлами или писали в чате, считается устаревшим.

## Два разных режима работы, не путать

**Пресейл-аудит — по умолчанию.** Делается до продажи, по холодному контакту, когда с компанией
ещё никто не разговаривал. Сюда относятся аудит 152-ФЗ и экспресс-разборы сайта для первого
касания. В этом режиме:

- **Не задавай вопросов про бизнес компании.** Выручка, средний чек, целевая аудитория, бюджеты,
  список конкурентов, приоритетные запросы — ответов нет и взять их негде.
- Работай только с тем, что видно снаружи: сайт, его разметка и подключаемые файлы, публичные
  реестры, поисковая выдача, открытые отзывы.
- Чего снаружи не видно — не выдумывай. Помечай «требует уточнения у клиента» и собирай в конце
  отчёта отдельным списком. Это нормальная часть пресейл-аудита.
- **Не отменяй и не приостанавливай работу из-за нехватки вводных.** Сделай по доступному и отдай
  результат. Единственная причина остановиться — сайт физически не открывается.

**Работа с клиентом, который уже платит.** Полное маркетинговое исследование по методологии
ConvertMonster, внедрение, документы по 152-ФЗ после оплаты. Здесь вводные собираются у клиента
как положено, вопросы задавать нужно, и правила пресейла выше не применяются.

Если непонятно, какой режим — спроси у меня одним вопросом: «это пресейл или клиент уже оплатил?»
и дальше работай по соответствующему режиму.

## Какую методику брать

| Запрос | Файл |
|---|---|
| Аудит по 152-ФЗ, персональные данные, политика, cookie | `audit-152fz.md` |
| Маркетинговый разбор, исследование, анализ конкурентов по холодному контакту | `market-express.md` |
| Полное маркетинговое исследование для оплатившего клиента | методика ConvertMonster, не этот репозиторий |

Если клиент холодный и никто с ним не разговаривал — это всегда пресейл, бери `market-express.md`,
а не полное исследование с брифом.

## Порядок работы над аудитом

1. `audit-152fz.md` — собрать материал и заполнить таблицу проверки. Ничего не писать в отчёт,
   пока таблица не заполнена.
2. Находки писать только по тому, что подтверждено таблицей. Не проверил — «требует ручной
   проверки», и в смету это не идёт.
3. Смета по ставке 2 500 ₽/час, скидка и её оформление — `rules-addu.md`.
4. Отчёт собрать по `report-structure.md` на базе `assets/report-template.html`. Свою вёрстку не
   придумывать.
5. Дисклеймер вставить дословно из `legal-disclaimer.md`.
6. Пройти самопроверку из `audit-152fz.md`. Если аудит занял меньше получаса, вернуться и открыть
   то, что пропущено.
7. Сохранить внутренний файл находок по `findings-template.md`.
8. Письмо клиенту — по `letters.md`.

## Куда сохранять результат

Всё по клиенту складывать в `audits/{домен}/` внутри этой папки:

```
audits/example.ru/
├── audit-example-ru.html      # клиентский отчёт, из него делается PDF
├── audit-findings.md          # внутренние находки, клиенту не показывать
└── letter.md                  # текст письма клиенту
```

Домен писать латиницей, точки оставлять (`example.ru`), для `.рф` использовать `-rf`.
Папка `audits/` в репозиторий не попадает, там данные клиентов.

## Обязательное

- Клиенту по 152-ФЗ уходит **PDF**, не HTML и не ссылка.
- Перед выдачей проверить, что часы на обложке, «Итого» в таблице и фиксированная сумма совпадают.
- Не писать «сайт незаконен» и «гарантируем отсутствие претензий Роскомнадзора».
- Если сайт не открылся — сказать честно, находки не выдумывать.
