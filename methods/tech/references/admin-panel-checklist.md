# Внутренний аудит в админке 1С-Битрикс (блоки A–F)

Делается при наличии доступа в админку. Подтверждает гипотезы внешнего контура.

## Блок A. Обновления и лицензия
Разделы: Marketplace → Обновление платформы / Установленные решения / Обновления решений.
Собрать: редакция продукта; активна ли лицензия; версия главного модуля; число рекомендуемых обновлений
и обновлений Marketplace; ошибки прошлых обновлений; обновлялся ли шаблон.
Вывод: много обновлений → нужен регламент; лицензия неактивна → нет обновлений безопасности;
старый шаблон → обновлять через копию.

## Блок B. Проверка системы
Раздел: Настройки → Инструменты → Проверка системы.
Собрать: соответствие мин./рекоменд. требованиям; PHP-версия и расширения; права на файлы/папки;
ошибки доступа; проверка отправки почты; сессии; структура БД.
Вывод: база технической надёжности; повторять после смены хостинга, обновлений, доработок.

## Блок C. Производительность
Разделы: Настройки → Производительность → Панель производительности / Таблицы / Страницы.
Собрать: итоговый показатель; самые тяжёлые страницы; медленные SQL; компоненты без кэша; размер кеша;
opcache/memcached.
Вывод: сайт — магазин, не визитка; скорость влияет на заявки/корзину/индексацию; оптимизация постоянная.

## Блок D. Безопасность
Разделы: Настройки → Проактивная защита → Панель безопасности / Сканер безопасности / Журнал вторжений / Контроль целостности.
Собрать: уровень панели безопасности; включён ли проактивный фильтр/WAF; веб-антивирус; критические события;
защита админки по IP; двухфакторная авторизация; результаты сканера.
Вывод: сайт собирает ПД и принимает заказы → безопасность это регулярная эксплуатация, а не разовый документ.

## Блок E. Резервные копии и восстановление
Собрать: где хранятся бэкапы; частота; включена ли БД; включены ли `/upload` и пользовательские файлы;
внешнее хранение; когда последний раз проверяли восстановление.
Вывод: бэкап без проверки восстановления — не гарантия; перед обновлениями обязателен бэкап и точка отката.

## Блок F. Интернет-магазин (регресс)
Проверить: оформление заказа; купить в один клик; запрос цены; обратный звонок; подписка; поиск; корзина;
избранное/сравнение; письма администратору; письма клиенту; антиспам; корректность целей аналитики.
Вывод: поддержка контролирует не «сайт открывается», а «заявки реально доходят».
