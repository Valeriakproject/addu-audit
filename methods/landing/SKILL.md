# Landing Page CRO Audit

Скилл для проведения быстрого эвристического CRO-аудита одностраничных сайтов за 1-2 часа — без доступа к аналитике клиента, на основе признанных CRO-фреймворков.

## Назначение и философия

Западные гуру (Peep Laja, Oli Gardner, MECLABS) сходятся в одном: полный CRO-процесс — это исследование, heatmaps, user testing, A/B тесты. Это правильно, но занимает недели и требует доступа к аналитике клиента — которого у фрилансера, как правило, нет.

**Наша цель — другая:**
1. **За 1-2 часа** дать клиенту ясный, приоритизированный список находок.
2. **Строго по эвристике** (никаких данных клиента не требуется): LIFT, CCD, MECLABS.
3. **Сразу с гипотезами** — не «надо улучшить заголовок», а «H1 формата X, потому что Y».
4. **Одностраничник = одна цель**. Если целей несколько — это не лендинг, а мини-сайт (другая методология).

Отчёт должен одновременно:
- Быть сдаваемым в presale (за 1 час демо-аудит — хороший продающий артефакт)
- Быть основанием для платного экспресс-аудита (2-4 часа работы)
- Быть точкой входа в абонентское обслуживание или продакшн-работу по лендингу

## Когда использовать

Скилл применим для:
- Рекламных лендингов под PPC (Директ, Google Ads, таргет)
- Quiz-лендингов, лид-магнитов, whitepaper-страниц
- Посадочных под SEO (одностраничные statys under long-tail)
- Продающих страниц инфопродуктов, курсов, вебинаров
- Presale-лендингов SaaS и B2B услуг

**НЕ используй** для:
- Интернет-магазинов → `estore-audit` (другая воронка: каталог/PDP/корзина/чекаут)
- Корпоративных многостраничников → `multi-page-cro-audit` (там AJTBD-сегментация и журнеи)
- Приложений и сервисов с авторизацией → нужна другая методология

---

## Методологическая база (итоговая связка)

- **LIFT Model** (WiderFunnel) — эвристическая линза на 6 факторов: Value Proposition, Relevance, Clarity, Distraction, Urgency, Anxiety.
- **7 Principles of Conversion-Centered Design** (Oli Gardner, Unbounce) — структурные правила: Attention Ratio 1:1, Context, Congruence, Credibility, Closing, Continuance.
- **MECLABS Conversion Sequence Heuristic** — веса при оценке приоритета: motivation (×4) > value prop (×3) > friction (×2) > anxiety (×-2).
- **PXL-упрощённый** (CXL) — объективная приоритизация гипотез через Impact × Effort вместо субъективного ICE.
- **Технический аудит** — Chrome DevTools MCP + audit-website skill (squirrelscan) для Core Web Vitals, mobile, SEO, broken links.

## Workflow

Каждый шаг подгружает соответствующий reference-файл через чтение.

### Шаг 0: Сбор контекста (5 мин)

Прежде чем что-то смотреть — уточни у пользователя (если не ясно):

1. **URL лендинга** — обязательно.
2. **Источник трафика**: PPC (Директ/Google Ads), SEO organic, таргет (ВК/Telegram Ads), cold outreach, другое. **Критично**: message match с источником — один из ключевых факторов LIFT.
3. **Целевое действие**: оставить заявку, записаться на демо, скачать гайд, купить, позвонить. **Должно быть одно** (если их несколько — первый же пункт в отчёте).
4. **Целевая аудитория**: B2B / B2C, сегмент, температура трафика (холодный/тёплый/горячий).
5. **Ниша**: услуги, инфопродукт, SaaS, физический товар (мелкий), мероприятие.
6. **Есть ли доступ к аналитике?** (Яндекс.Метрика, Clarity, GA4) — если да, работа расширяется; если нет (типовой случай) — чисто эвристика.
7. **Глубина аудита**:
   - **Экспресс** (1-1.5 часа) — только находки + приоритизация, без подробных гипотез (для presale).
   - **Стандарт** (2-3 часа) — с подробными гипотезами, скриншотами, техаудитом (для платного аудита).

Если данных нет — работай на эвристике и явно помечай в отчёте.

### Шаг 1: Первичное сканирование лендинга (10 мин)

**Открыть лендинг через Chrome DevTools MCP** в двух эмуляциях:

```
1. mcp__chrome-devtools__new_page → URL
2. mcp__chrome-devtools__resize_page → 1440x900 (desktop)
3. mcp__chrome-devtools__take_screenshot (scroll to capture full page)
4. mcp__chrome-devtools__emulate → iPhone 14 Pro
5. mcp__chrome-devtools__take_screenshot (mobile)
6. mcp__chrome-devtools__list_console_messages
7. mcp__chrome-devtools__list_network_requests
```

Собери **первое впечатление за 5 секунд** (blink test):
- Что это за продукт? Для кого? Почему мне это нужно?
- Где тут CTA? Что надо сделать?
- Доверяю я этому или нет?

Запиши реакцию «холодного посетителя» — это будет первым абзацем в отчёте.

### Шаг 2: Эвристический аудит по LIFT + CCD (30-40 мин)

**Прочитай `heuristics-checklist.md` целиком** — это основной инструмент.

Там разобраны:
- LIFT — 6 факторов с вопросами для каждого
- CCD — 7 принципов с акцентом на Attention Ratio
- Структурные блоки лендинга (hero, offer, proof, form, CTA, FAQ, футер)
- Mobile-specific проверки
- Trust-элементы для РФ

**НЕ** проходи весь чеклист формально — ищи **5-8 крупных проблем**, которые реально снижают конверсию. Остальные можно упомянуть в «приложении».

Принцип отбора находки: **«это мешает конкретному пользователю из целевой аудитории конвертироваться прямо сейчас?»** Не «а можно ещё сделать…», а «из-за этого человек уходит».

### Шаг 3: Технический аудит (15-20 мин)

Прогони через инструменты:

1. **Chrome DevTools MCP**:
   - `mcp__chrome-devtools__performance_start_trace` + `performance_stop_trace` + `performance_analyze_insight` → Core Web Vitals (LCP, CLS, INP)
   - `list_network_requests` → вес страницы, 4xx/5xx, блокирующие ресурсы
   - `list_console_messages` → JS-ошибки, проблемы с трекингом

2. **audit-website skill (squirrelscan)** — 230+ правил за один проход: SEO, meta, broken links, security, content. **Используй обязательно** — это быстрый дополнительный слой находок.

Всё это собирается в раздел «Технический аудит» отчёта. Если нет критичных находок (скорость ОК, Core Web Vitals в норме) — раздел короткий. Если проблемы есть — это отдельные находки с высоким приоритетом.

### Шаг 4: Российская специфика (5-10 мин)

**Прочитай `russian-landing-specifics.md`.**

Коротко — что часто упускают западные чеклисты и что критично для РФ:
- 152-ФЗ на формах (согласие на ОПД, ссылка на политику)
- Платёжные логотипы (СБП, Мир) для B2C
- Яндекс.Метрика вместо GA4 + карта кликов/вебвизор
- Чат-виджеты и мессенджеры (Telegram, WhatsApp, JivoChat)
- Юр. реквизиты и ИП/ООО в футере (критично для доверия в B2B)
- Квизы как способ микроконверсии (в РФ работают особенно хорошо)
- Специфика рекламных источников (Директ vs таргет ВК — разные ожидания)

### Шаг 5: Приоритизация находок (10-15 мин)

**Прочитай `prioritization.md`** — упрощённый PXL-подход.

Для каждой находки оцени:
- **Impact (1-5)** — насколько влияет на конверсию. Учитывай веса MECLABS: проблемы с motivation/value prop × больший коэффициент, чем с anxiety.
- **Effort (1-5)** — сложность внедрения. Копирайт = 1, новый блок = 2-3, дизайн + вёрстка = 3-4, разработка/интеграция = 5.
- **Priority = Impact / Effort** → сортировка, группировка.

Группируй:
- **Quick Wins** (1-2 недели, копирайт + мелкие блоки) — то, что можно внедрить уже завтра
- **Medium** (1 месяц, дизайн + вёрстка) — существенные изменения
- **Long-term** (2-3 месяца, разработка или редизайн секций)

### Шаг 6: Собрать отчёт (20-30 мин)

**Прочитай `report-template.md`** — там готовый шаблон.

**Где сохранять отчёт:**

Рабочий черновик (источник правды, база наработок):
- Путь: `landing_page_audit/audits/{YYYY-MM-DD}-lp-audit-{client-slug}.md`
- Markdown, складывается в `audits/` внутри скилла. Скриншоты — в `audits/{client-slug}-assets/`.

Клиентская выдача — **самодостаточный HTML в едином дизайне** (стиль Notion + брендинг addu.ru):
- **Обязательно прочитай `../assets/design-system.md` и следуй ему.**
- Скопируй болванку `../assets/base-template.html` в `output/{client-slug}/index.html`,
  перенеси находки в JS-массивы, напиши render-функции. Вкладки: TL;DR / Находки /
  Scorecard (LIFT) / Тех-аудит / Следующие шаги.
- Открой результат в браузере (Chrome DevTools MCP) и проверь все вкладки.
- Если нужна PDF-версия — печать HTML в PDF из браузера или Pandoc из MD-черновика.
- **Публикация для клиента (обязательно):** это маркетинговый аудит — публикуй клиентский HTML на
  **https://case.addu.ru/**, клиенту отправляй ссылку, а не файл. Процедура и доступы —
  `../assets/publish-case-addu.md`, **пароль не запрашивать**. Ссылка: `https://case.addu.ru/{client-slug}/`.

Основные разделы отчёта:
1. TL;DR — 3-5 буллетов
2. Scorecard — таблица по LIFT и блокам
3. Quick Wins — подробные находки с гипотезами
4. Medium / Long-term
5. Технический раздел
6. Рекомендации по аналитике и следующим шагам

## Принципы составления отчёта

### Тон

- **Не упрекай клиента.** «У вас плохой H1» → «На H1 скрыт потенциал — сейчас он описывает что мы, а не что это даст клиенту».
- **Расшифровывай термины** при первом упоминании: CRO, CTA, LIFT, Core Web Vitals.
- **Давай конкретику.** Не «улучшите заголовок», а «H1 формата [Результат] [за счёт чего] [для кого] — например, "Запустим трафик на ваш сайт за 2 недели с оплатой за заявки"».
- **Подтверждай источниками.** LIFT → WiderFunnel, принципы — Oli Gardner (Unbounce), цифры — Baymard или публичные кейсы.

### Структура каждой находки

1. **Observation** — что сейчас (со скриншотом или цитатой).
2. **Why it matters** — связь с LIFT/CCD/MECLABS-фактором, эффект на поведение.
3. **Hypothesis** — «Если {изменение}, то {метрика} вырастет, потому что {причина}».
4. **Priority** — Impact X/5, Effort Y/5 → Quick Win / Medium / Long-term.

### Что НЕ писать в отчёт

- Микро-замечания (шрифт на 1px, оттенок кнопки). Если это действительно важно — объедини с блоком «визуальная иерархия».
- Голые гипотезы без обоснования: «давайте попробуем красную кнопку». Красная кнопка без гипотезы и контекста — это не CRO, это угадайка.
- Рекомендации, которые нельзя внедрить без редизайна всего лендинга — если только это не стратегическая находка в Long-term.
- Рекомендации из чужой ниши без адаптации: «делайте как на Stripe» — плохо. «Для вашей B2B SaaS аудитории подходит подход Stripe с акцентом на developer experience и конкретные числа» — хорошо.

## Частые ошибки, которых избегать

1. **Формальный проход по чеклисту** — клиент получит «галочки по 60 пунктам» и не поймёт, что делать. Лучше 5 глубоких находок.
2. **Игнорирование source-fit** (message match): лендинг хорош сам по себе, но не соответствует PPC-объявлению → конверсия падает. Всегда спрашивай про источник трафика.
3. **Лендинг без одной цели**: если на странице 3 CTA на разные продукты — первая же находка должна быть «нарушен Attention Ratio 1:1».
4. **Пропуск мобильной версии**: в РФ 65-75%+ трафика с мобилок на лендингах (особенно таргет). Аудит без mobile — половинчатый.
5. **Технический аудит отдельно**: Core Web Vitals напрямую влияют на конверсию (каждая секунда LCP сверх 2.5s = -7% конверсии по данным Google). Не откладывай.
6. **Копирование западных паттернов**: hero с видео-фоном работает в США, а в РФ на Директ-трафике может убивать конверсию (долгая загрузка, низкий Trust к «маркетинговым» видео). Смотри `russian-landing-specifics.md`.
