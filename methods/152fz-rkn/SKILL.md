# Addu 152-ФЗ — Инструкция по уведомлению РКН

Четвёртый (опциональный) шаг конвейера. Генерирует клиентскую HTML-инструкцию по подаче уведомления в Роскомнадзор — простую, пошаговую, с уже подставленными реквизитами и ответами по каждому полю формы.

## Когда использовать

- `addu-152fz-generate` уже отработал (есть `answers.md`, `policy.md`, `audit-findings.md`).
- Клиент не знает, подано ли уведомление РКН, или явно просит помочь с этим.
- Менеджер хочет дать клиенту готовую инструкцию «что вводить в каждое поле».

Не использовать:
- если ещё нет `answers.md` (нет реквизитов оператора) — сначала `addu-152fz-generate`;
- если клиент однозначно подтвердил, что уведомление уже подано.

## Вход

- **Slug клиента** (обязательно). Skill ищет файлы в `documents/{slug}-152fz/`:
  - `answers.md` — обязателен (реквизиты оператора);
  - `audit-findings.md` — обязателен (обработчики, формы, CMS, URL сайта);
  - `policy.md` — желателен (список обработчиков и целей).

## Что делает

### Шаг 1. Сбор данных для персонализации

Читает `answers.md` и `audit-findings.md`. Извлекает:

- `operator_full_name`, `operator_inn`, `operator_ogrn`, `operator_legal_address`, `operator_mail_address` — для поля 1 формы РКН;
- URL сайта, тип бизнеса, формы на сайте — для формулировки целей обработки (поле 2);
- категории ПДн с сайта (имя, телефон, email и т.д.) — для поля 3;
- категории субъектов (физические лица — клиенты, посетители, соискатели) — для поля 4;
- правовые основания — стандартный набор плюс специфика клиента — для поля 5;
- список обработчиков (хостинг, аналитика, чаты, CRM, платёжки) с адресами серверов — для поля 10.1;
- наличие трансграничной передачи — для поля 10.

### Шаг 2. Копирование скриншотов

Перед генерацией HTML скопировать скриншоты из skill-assets в папку клиента:

```powershell
$src = "<TOOLKIT_ROOT>/.claude/skills/addu-152fz-rkn/assets/screenshots"
$dst = "documents/{slug}-152fz/rkn-screens"
if (!(Test-Path $dst)) { New-Item -ItemType Directory $dst }
Copy-Item "$src\*.png" $dst
```

Toolkit root — это папка, где находится `.claude/`. Определить по текущей рабочей директории.

### Шаг 3. Генерация HTML-инструкции

Создать `documents/{slug}-152fz/rkn-instruction.html`.

Инструкция должна быть:
- **простой** — не юридический документ, а пошаговый гайд «что нажать, что ввести»;
- **персонализированной** — в каждом блоке поля стоит готовый ответ с реальными данными клиента, выделен рамкой/цветом, скопировать одним кликом;
- **со скриншотами** — каждый шаг сопровождается скриншотом из `./rkn-screens/page_N.png`;
- **с тремя вариантами подачи** — онлайн через портал РКН, через Госуслуги (с УКЭП), Почтой России;
- **готова к печати / PDF** — одна HTML-страница, A4.

HTML-структура:
1. Шапка: логотип Addu, заголовок «Инструкция: уведомление РКН», имя клиента/сайт, дата.
2. Блок «Зачем это нужно» — 3-4 строки про штрафы и требование 152-ФЗ.
3. Блок «Три способа подать» — карточки: онлайн (рекомендуем), Госуслуги, Почта.
4. Основной раздел «Онлайн: что вводить в каждое поле» — 11 полей формы по `references/rkn-form-fields.md`.
5. Раздел «Если подаёте через Госуслуги» — краткие отличия со скриншотами стр. 1-2.
6. Блок «После подачи» — что ждать, где проверить статус.
7. Контактный блок Addu.

### Шаг 4. Персонализация каждого поля

Для каждого из 11 полей формы — блок вида:

```
Поле 1. Тип и наименование оператора
[скриншот страницы формы]
Что выбрать/ввести:
┌────────────────────────────────────────────────┐
│ Общество с ограниченной ответственностью «СК Логист и Ко» │
│ ИНН: 5044084631   ОГРН: 1125044003072          │
│ Адрес: 141554, Московская область, ...         │
└────────────────────────────────────────────────┘
💡 Подсказка: выберите «Юридическое лицо», укажите наименование точно как в ЕГРЮЛ.
```

Текст внутри рамки — уже заполненный ответ под конкретного клиента.

### Шаг 5. Поле 10.1 — где хранятся данные (обработчики)

Это самое сложное поле. Для каждого обработчика из findings/policy.md — отдельная строка с адресом сервера. Использовать референс `references/rkn-form-fields.md` раздел «Адреса серверов обработчиков» — там готовые строки для типовых сервисов (REG.RU, Яндекс, Jivo и т.д.).

### Шаг 6. Сообщение в чат

После создания файлов:
- путь к `rkn-instruction.html`;
- краткий список из 3-4 ключевых вещей, которые клиент должен подтвердить перед подачей (дата начала обработки, наличие УКЭП для Госуслуг, статус старого уведомления если было);
- одна строка менеджеру: «Отправить клиенту вместе с PDF-версией инструкции (Ctrl+P из браузера)».

## Что НЕ делает

- Не подаёт уведомление за клиента (нет доступа к Госуслугам и порталу РКН).
- Не гарантирует принятие уведомления — это зависит от корректности реквизитов клиента.
- Не заменяет юридическую проверку — если у клиента нестандартная ситуация (здравоохранение, дети, биометрия, госструктуры), инструкция требует доработки.
- Не повторяет общий check-лист документов — это уже сделал `addu-152fz-generate`.
