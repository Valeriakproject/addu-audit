# Что считать достаточным ответом по каждому required-ключу

Skill `addu-152fz-generate` валидирует ответы из `answers.md` по этому списку. Если ключ помечен `required` в `intake-context.md` и НЕ удовлетворяет критериям ниже — генерация останавливается.

## operator_legal_form

Достаточно: одно из значений «ООО», «АО», «ИП», «самозанятый», «физлицо», или их вариации.
Не достаточно: «компания», «фирма», пусто.

## operator_full_name

Достаточно: строка с указанием организационно-правовой формы и наименования. Примеры:
- «ООО "Ромашка"»
- «Индивидуальный предприниматель Иванов Иван Иванович»
- «ИП Иванов И.И.»

Не достаточно: только торговая марка («Ромашка»), только домен («ромашка.ру»).

## operator_inn

Достаточно: 10 цифр (для юр.лиц) или 12 цифр (для ИП). Если в ответе указано «не знаю» — спросить менеджера, может ли он сам найти ИНН на nalog.ru по названию (часто это быстрее, чем ждать клиента).

## operator_ogrn

Достаточно: 13 цифр (ОГРН для юр.лиц) или 15 цифр (ОГРНИП для ИП). Та же логика с «не знаю».

## operator_legal_address

Достаточно: строка с городом, улицей, домом. «г. Москва» одна — недостаточно, нужен полный адрес.

## operator_pd_email

Достаточно: валидный email. Допустимо, чтобы это был тот же контактный email с сайта.

## hosting_provider

Достаточно: название провайдера (REG.RU, TimeWeb, Beget, Rusonyx, Selectel, и т.д.) или «собственный сервер» / «свой VPS» / «арендуем у дата-центра X».

## has_marketing_rasslyka

Достаточно: однозначное «да» / «нет».
Если «да» — должны быть указаны хотя бы каналы (`marketing_channels`).
Если «нет» — допустимо без `newsletter_service`.

## payment_service (требуется только если есть корзина)

Достаточно: название платёжной системы (Yookassa / CloudPayments / Тинькофф Касса / Сбербанк / иное) ИЛИ «оплата только по счёту / наличными при получении / без онлайн-оплаты».

## rkn_notification

Достаточно: «да, номер X от дата Y» ИЛИ «нет, не подавали».
«Не знаю» по этому пункту — приемлемо: в выходных документах пометить «не уточнено», в notes-and-sources вывести в задачи менеджеру.

## cms_access

Достаточно: «да, создадим пользователя» / «да, доступ уже передан» / «да, через разработчика клиента» / «нет, работу делает наш разработчик, нужно ТЗ».

Если «нет» — это не блокирует генерацию, но в `notes-and-sources.md` отметить, что внедрение пойдёт через разработчика клиента — наш разработчик нужен только консультантом.

## Что НЕ блокирует генерацию

Если в `answers.md` отсутствует ключ из `expected` или `optional` — это нормально:
- `email_service` — подставить «корпоративная почта оператора»;
- `crm` — упомянуть только если упомянут в `where_leads_go`;
- `telephony` — пропустить целиком;
- `yandex_metrika_counter` — пропустить блок про Метрику в политике;
- `delivery_service` — подставить «выбранная клиентом служба доставки» (общая формулировка);
- `pixels`, `calltracking`, `chat_widget` — пропустить.

## Уточняющие вопросы менеджеру через AskUserQuestion

Допустимы, но **не больше 3 за прогон**. Случаи:
- ответ клиента содержит противоречие;
- ответ клиента двусмысленный (например, «у нас почта вся в Mail.ru, но домен сейчас на Я.360»);
- клиент перечислил несколько вариантов через запятую и непонятно, какой основной.

Если возможных уточнений больше 3 — лучше остановиться и попросить менеджера пройти по answers.md ещё раз.
