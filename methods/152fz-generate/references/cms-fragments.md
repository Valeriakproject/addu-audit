# CMS-специфичные фрагменты

Используются в `action-plan.md`, `form-checkboxes.md`, `cookie-banner.md`. Подставляются на основе CMS из `intake-context.md`.

## Bitrix

### Доступ

```text
Создать пользователя в админке Bitrix с правами на:
- редактирование страниц (Контент → Структура);
- редактирование файлов шаблона `/bitrix/templates/{{TEMPLATE_NAME}}/`;
- управление веб-формами (Сервисы → Веб-формы);
- управление модулем подписок (Сервисы → Подписка);
- доступ к `.htaccess` или к настройкам перенаправлений Bitrix.
```

### Создание страниц

```text
В админке Bitrix: Контент → Структура → корень сайта → Добавить страницу. Тип: «Обычная страница». В качестве URL указать `/policy/` (или `/personal-data-consent/`). Включить в меню — нет (попадёт в footer через шаблон).
```

### Редирект /personal-info/ → /policy/

```text
Варианты:
1. `.htaccess` (Apache): добавить `RewriteRule ^personal-info/?$ /policy/ [R=301,L]`.
2. Bitrix-обработчик `OnBeforeProlog` с `LocalRedirect('/policy/', false, '301 Moved permanently')`.
3. Модуль «Управление структурой» → раздел «Редиректы» (если установлен).
```

### Обязательность чекбокса в веб-форме

```text
Админка: Сервисы → Веб-формы → Список форм → выбрать форму → Вопросы → найти поле `personalInfo` → отметить «Обязательное: Да». Сохранить.

Если форма реализована своим JS-обработчиком, добавить серверную проверку в скрипте обработчика:

```php
if ($_POST['personalInfo'] !== 'Y') {
    return ['error' => 'Необходимо согласие на обработку персональных данных'];
}
```
```

### Регистрация Bitrix

```text
Поле `USER_PERSONAL_INFO` уже обязательно через `data-required="Y"`. Дополнительно — обработчик события:

```php
AddEventHandler("main", "OnBeforeUserRegister", function(&$arFields) {
    if ($arFields['USER_PERSONAL_INFO'] !== 'Y') {
        global $APPLICATION;
        $APPLICATION->ThrowException('Необходимо согласие на обработку персональных данных');
        return false;
    }
});
```
```

### Подписка Bitrix

```text
Штатный обработчик `subscr_edit.php` не предусматривает поле согласия. Варианты:
1. Заменить форму на свой AJAX-обработчик с проверкой двух чекбоксов перед вызовом `CSubscription::Update()`.
2. Подключить prepend-обработчик `OnBeforeSubscriptionAdd` и проверять `$_POST['personalInfo']` и `$_POST['marketing']`.
```

### Cookie-баннер

```text
Вставить разметку из `cookie-banner.md` в шаблон `/bitrix/templates/{{TEMPLATE_NAME}}/footer.php` перед закрывающим `</body>`. Стили положить в `template_styles.css` шаблона.
```

## Tilda

### Доступ

```text
Добавить сотрудника в проект через раздел «Сотрудничество» в настройках проекта. Не присылайте пароль от аккаунта Tilda — добавьте нашего разработчика как соавтора с правами «Может редактировать».
```

### Создание страниц

```text
Сайт → Создать новую страницу → выбрать пустой шаблон → блок «Текст и заголовки» (T030) → вставить markdown-текст из черновика. URL страницы — задать в настройках страницы (раздел «Настройки страницы → Адрес страницы»).
```

### Чекбокс в форме

```text
Открыть форму в редакторе → добавить поле типа «Галочка» (Checkbox) → настройки: «Обязательное: Да», «Отмечено по умолчанию: Нет». В тексте подписи — вставить HTML с двумя ссылками. Если Tilda обрезает HTML в подписи — использовать обходной вариант: одна ссылка в подписи + дополнительный текстовый блок T155 под формой с обеими ссылками.
```

### Cookie

```text
Использовать стандартный блок Tilda T972 (Cookies). Настроить: текст из `cookie-banner.md`, ссылка на /policy/.
```

### Tilda Leads / трансграничная передача

```text
В политике обязательно описать платформу Tilda как обработчика. По публичному поручению Tilda могут привлекаться субобработчики (Hetzner, G-Core, Google Cloud) — это нужно отразить.
```

## WordPress

### Доступ

```text
Создать пользователя с ролью Administrator. Для безопасности — лучше через плагин временных доступов (Temporary Login Without Password), либо передать через защищённый канал и удалить после сдачи работ.
```

### Создание страниц

```text
Админка → Страницы → Добавить новую → заголовок «Политика обработки персональных данных» → постоянная ссылка `/policy/` → вставить содержимое политики в визуальный редактор или блок «Произвольный HTML». Опубликовать.
```

### Чекбоксы в формах

```text
Зависит от плагина форм:
- Contact Form 7: добавить тег `[acceptance personalInfo]` с текстом и ссылками; в настройках формы — «Согласие» как обязательное.
- WPForms: добавить поле «GDPR Agreement», обязательное, текст с ссылками.
- Gravity Forms: добавить поле «Consent», установить обязательность.

Серверная валидация работает на уровне плагина.
```

### Подписки

```text
Если используется плагин email-маркетинга (Mailchimp for WP, Newsletter, MailPoet) — настроить два чекбокса согласия в виджете подписки. Pre-checked отключить в настройках плагина.
```

### Cookie

```text
Использовать плагин Cookie Notice & Compliance (Hu-manity) или Complianz. Настроить текст из `cookie-banner.md`, ссылку на /policy/.
```

## Modx / Drupal / Joomla / самописная

### Доступ

```text
Создать отдельную учётную запись CMS с минимально необходимыми правами на:
- редактирование страниц;
- редактирование шаблонов;
- работу с формами;
- настройку редиректов.

Если CMS самописная — передать контакт разработчика клиента или выдать прямой доступ к репозиторию.
```

### Реализация

```text
Конкретные шаги зависят от структуры конкретного решения. Наш разработчик после получения доступа уточнит у разработчика клиента архитектуру и адаптирует ТЗ.
```
