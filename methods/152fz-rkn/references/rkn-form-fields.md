# Поля формы уведомления РКН — справочник

Форма подачи уведомления: https://pd.rkn.gov.ru/operators-registry/notification/form/
Та же форма доступна через Госуслуги → профиль → «Все организации и роли» → раздел Роскомнадзора.

Всего 11 полей. Ниже — что куда вводить, допустимые значения и подсказки.

---

## Поле 1. Тип и наименование оператора

**Что заполнить:**
- Тип субъекта права: одно из «Юридическое лицо» / «ИП» / «Физическое лицо»
- Наименование: полное название из ЕГРЮЛ/ЕГРИП (для ООО — с кавычками и заглавными буквами)
- ФИО руководителя: как в ЕГРЮЛ
- ИНН, ОГРН/ОГРНИП
- Юридический адрес (по ЕГРЮЛ)
- Почтовый адрес (если отличается — указать, иначе — тот же)

**Подсказки:**
- Наименование вводить точно как в ЕГРЮЛ (проверить на nalog.ru → «Сведения о юрлицах»)
- Если подаёте как ИП — вводить «Индивидуальный предприниматель Фамилия Имя Отчество»
- Почтовый адрес — тот, на который РКН может прислать письмо; если офис другой — указать офис

## Поле 2. Цель обработки персональных данных

**Что вводить:** текстовое описание — для чего вы собираете данные. Указывать конкретно, но не слишком детально.

**Типовые варианты:**

Для сайта с формами заявок (B2B/B2C услуги):
```
Приём, обработка и исполнение заявок потенциальных клиентов; обратная связь
по обращениям; ведение внутреннего учёта клиентов и истории взаимодействия
```

Для интернет-магазина:
```
Заключение и исполнение договора купли-продажи, доставка товара, обработка
платёжных операций, обратная связь по заказам, проведение программ лояльности
```

Для сайта с формой подписки:
```
Приём заявок, обратная связь; предоставление информации по запросу;
информирование о новостях и акциях компании (при наличии согласия)
```

**Важно:** если есть несколько разных форм с разными целями — перечислить все. Каждая цель = одна строка.

**Скриншот:** page_4.png

## Поле 3. Категории персональных данных

**Что вводить:** перечень типов данных, которые собирает сайт.

**Стандартный набор для лид-форм:**
```
Фамилия, имя, отчество; номер контактного телефона; адрес электронной почты;
содержание обращения
```

**Для интернет-магазина добавить:**
```
Адрес доставки (страна, регион, город, улица, дом, квартира, индекс);
сведения об оплате (без данных карты — они у платёжной системы);
история заказов
```

**Для сайта с регистрацией:**
```
Логин, пароль (в зашифрованном виде)
```

**Специальные и биометрические категории:**
Если НЕ собираете — так и написать: «Специальные категории персональных данных не обрабатываются».
Если собираете (здоровье, биометрия) — требуется отдельная консультация юриста.

**Скриншот:** page_4.png, page_5.png

## Поле 4. Категории субъектов

**Что вводить:** кто является субъектом ПДн — физические лица, чьи данные вы обрабатываете.

**Типовые варианты:**
```
Физические лица — клиенты и потенциальные клиенты оператора
```
```
Физические лица — клиенты оператора, посетители сайта
```
```
Физические лица — клиенты оператора, сотрудники и соискатели вакансий
```

Если клиентами являются только юрлица, но контактные лица — физлица:
```
Физические лица — контактные лица организаций-клиентов оператора
```

**Скриншот:** page_5.png

## Поле 5. Правовые основания обработки

**Что вводить:** перечень оснований из ст. 6 и 9 152-ФЗ.

**Стандартный набор для большинства сайтов:**
- ✅ Федеральный закон от 27.07.2006 № 152-ФЗ «О персональных данных»
- ✅ Согласие субъекта персональных данных

**Если есть интернет-магазин (договор):**
- ✅ Договор, стороной которого является субъект ПДн (оформление и исполнение заказа)
- ✅ Федеральный закон от 06.12.2011 № 402-ФЗ (бухучёт — данные для документов)

**Если есть сотрудники:**
- ✅ Трудовой кодекс Российской Федерации

**Что НЕ выбирать** без консультации юриста:
- «Жизненно важные интересы» — только в исключительных ситуациях
- «Осуществление правосудия» — только суды

**Скриншот:** page_5.png, page_6.png

## Поле 6. Перечень действий с персональными данными

**Что вводить:** что вы делаете с данными.

**Стандартный набор:**
```
Сбор, запись, систематизация, накопление, хранение, уточнение (обновление,
изменение), извлечение, использование, передача (предоставление, доступ),
обезличивание, блокирование, удаление, уничтожение персональных данных.
Обработка осуществляется с использованием средств автоматизации и без
использования таких средств.
```

## Поле 7. Описание мер по обеспечению безопасности

**Что вводить:** какие меры защиты применяете.

**Стандартный набор для сайта:**
```
Организационные меры: ограничение доступа к персональным данным,
ознакомление сотрудников с требованиями 152-ФЗ, назначение ответственного
лица за организацию обработки персональных данных.
Технические меры: использование защищённого соединения HTTPS при
передаче данных; разграничение прав доступа в информационных системах;
использование антивирусного ПО; регулярное резервное копирование.
```

**Скриншот:** page_6.png, page_9.png

## Поле 8. Дата начала обработки

**Что вводить:** дата, когда вы начали обрабатывать персональные данные.

**Как определить:**
- Обычно это дата запуска сайта с формами, или дата регистрации компании — что раньше.
- Если компания существует давно — можно указать дату создания (по ОГРН: первые 2 цифры = год; 112... = 2012).
- Если точная дата неизвестна — указать приблизительно «1 января [год создания компании]».

**Подсказка:** дата не может быть позже сегодняшней. РКН не штрафует за «позднюю» дату начала, если уведомление подано сейчас впервые.

**Скриншот:** page_7.png

## Поле 9. Условия прекращения обработки

**Что вводить:** когда вы перестанете обрабатывать данные.

**Стандартный текст:**
```
Обработка персональных данных прекращается при достижении целей обработки,
отзыве согласия субъектом персональных данных, а также при прекращении
деятельности оператора. После прекращения обработки персональные данные
уничтожаются в сроки, установленные законодательством.
```

## Поле 10. Трансграничная передача

**Что выбрать:** «Да» или «Нет».

**Когда «Нет»:**
- Все сервисы (хостинг, аналитика, чаты) работают на серверах в России.
- Нет Google Analytics, Facebook Pixel, иностранных платёжных систем, иностранных CRM.

**Когда «Да»:**
- Используется Google Analytics, Facebook/Meta Pixel, иностранный хостинг, зарубежная CRM.
- Нужно дополнительно указать: в какие страны передаются данные, и есть ли там «адекватная защита».

**Если «Да» — страны с «надлежащей защитой»** (ратифицировали Конвенцию Совета Европы):
Австрия, Германия, Франция, Великобритания, Нидерланды, Ирландия и др. страны ЕС + ряд других. США — НЕТ в этом списке (нужна дополнительная правовая основа).

## Поле 11. Средства обеспечения безопасности

**Что вводить:** конкретные средства и меры защиты.

**Для большинства сайтов:**
- Организационные меры, регламентирующие работу с персональными данными в компании (приказы, инструктажи, ограничение доступа).
- Антивирусное ПО, установленное на рабочих местах.
- Использование HTTPS при передаче данных через сайт.
- Разграничение прав доступа к информационным системам, обрабатывающим ПДн.
- Регулярное резервное копирование данных.

Формально выбирать из списка в форме: «Организационные меры», «Технические и программные меры», «Криптографические средства» (если используется HTTPS — можно отметить), «Физические меры» (если есть охраняемый офис/сервер).

## После подачи

- Уведомление рассматривается в течение **30 дней** (на практике быстрее).
- Статус можно проверить на: https://pd.rkn.gov.ru/operators-registry/operators-list/
- При принятии оператор получает **регистрационный номер** — сохранить его.
- Если данные о компании изменились (адрес, ИНН, состав обработчиков) — подать **изменение в реестр** через тот же портал.

## Что не входит в уведомление

Следующее НЕ нужно прикладывать к онлайн-уведомлению, но нужно иметь внутри компании:
- Политику обработки ПДн (уже сделана — policy.md)
- Согласие (уже сделано — personal-data-consent.md)
- Приказ о назначении ответственного лица (ст. 22.1 152-ФЗ)
- Договоры-поручения с обработчиками (Jivo, хостинг и т.д.)
- Регламент хранения и удаления ПДн
