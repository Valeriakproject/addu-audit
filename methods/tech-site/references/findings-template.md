# Шаблон tech-findings.md

Внутренний машиночитаемый файл аудита. Формат стабильный (по образцу `audit-findings.md` из 152-ФЗ-конвейера), чтобы его можно было переиспользовать и сравнивать между прогонами.

## Жёстко требуется

- Шапка: дата, сайт, платформа/CMS, тип бизнеса, health-score SquirrelScan (если есть).
- Раздел `## Сводка` с таблицей severity.
- Раздел `## Проверенные страницы` — список URL, что открывали.
- Раздел `## Обнаруженные формы` — каждая форма с полями, action-эндпоинтом и статусом обвязки.
- Раздел `## Технические находки` — каждая `### N. {Заголовок}` с полями `Зона`, `Где проверяли`, `Что нашли`, `Severity`, `Почему важно`, `Рекомендация`, `Чем выявлено` (squirrel/chrome/оба).
- Раздел `## Оценка работ` — таблица время/стоимость + итоговая фиксированная сумма.
- Раздел `## За пределами технического объёма` — что требует доступов/бэкенда/отдельной оценки.

## Допустимые значения severity

- `hard_fail` — ломает работу для пользователя (страница не открывается, ключевая кнопка/форма не работает, JS-ошибка ломает функционал, сайт без HTTPS целиком);
- `risk_flag` — заметный дефект (битые ссылки/картинки, mixed-content, медленно, поломки на мобильном, mojibake);
- `manual_review` — нельзя подтвердить из открытой части (доставка заявок в CRM, бэкенд, нагрузка, кросс-браузерность);
- `ok` — проверено, проблем нет.

Не выдумывать другие значения.
